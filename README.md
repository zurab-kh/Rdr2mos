# RDR2 Co-op — сюжет Red Dead Redemption 2 вместе

Мод для **сюжетного режима** RDR2 на ПК: несколько игроков (до 8) проходят историю вместе
через общий сервер. Катсцены смотрят все.

> **Статус: экспериментальная версия 0.6.** Сетевое ядро, сервер и вся логика синхронизации
> покрыты автотестами (симуляция мира и сети с задержками, джиттером и потерями), плагин
> собирается под Windows, но **в самой игре он ещё не обкатан** — у меня нет возможности
> запустить RDR2 в среде разработки. См. [«Что проверить в игре»](#что-проверить-в-игре-первым-делом).

Работает только в сюжетном режиме, к Red Dead Online отношения не имеет.

## Как это устроено

```
   игрок A (владелец мира)          игрок B             игрок C
        │   RDR2 + мод                │                    │
        └──────────────┐              │              ┌─────┘
                       ▼              ▼              ▼
                 ┌──────────────────────────────────────┐
                 │            rdr2coop-server           │
                 │  кампании · сохранения · журнал ·    │
                 │  игроки · копия мира · сюжет         │
                 └──────────────────────────────────────┘
```

**Сервер — центр всего.** Он:

- ведёт **кампании** (несколько сразу, по имени, с паролем на сервер);
- **хранит сохранения кампании с историей версий** (последние 20). Новое сохранение владельца
  мира попадает на сервер автоматически, и любой игрок может скачать его даже тогда, когда
  владельца нет в сети. Хранится и после перезапуска сервера;
- ведёт **журнал прохождения** (кто вошёл и вышел, начатые и законченные миссии, смерти,
  сохранения) и **список игроков** (когда был, где находился);
- держит **копию состояния мира**: подключившийся игрок видит мир сразу, не дожидаясь обновлений;
- **решает сюжетные вопросы**: старт миссий, барьер катсцен, общий провал миссии, сверка миссий;
- выбирает **владельца мира** и при его выходе **передаёт мир** следующему игроку;
- пересылает состояние игроков и мира, а урон — тому, кто владеет целью.

**Почему мир просчитывает игра, а не сервер.** ИИ, физика и скрипты миссий RDR2 могут работать
только внутри игры, поэтому мир просчитывает игра одного из игроков — **владельца мира**.
Остальные видят его NPC, лошадей и транспорт как «зеркала», а свою массовку отключают.
Каждый управляет своим персонажем сам, без задержки ввода.

## Сюжет вместе

Режим выбирается на сервере (`--mode`) и одинаков для всех в кампании.

### `shared` — общий сюжет (по умолчанию). Катсцены смотрят все

Все играют **одно и то же сохранение кампании**, поэтому миссия идёт в каждой игре, и каждый видит
настоящие катсцены — с анимацией, озвучкой и субтитрами. Сервер держит прохождения в такт.

| Что | Как работает |
|---|---|
| Одинаковое сохранение | Сохранение кампании лежит на сервере. **`F10`** скачивает его в свободный слот (`SRDR30000`…`SRDR30014`; свои сохранения не перезаписываются, целостность проверяется по CRC-32), затем загрузите его: пауза → Сюжет → Загрузить игру. Новая кампания начинается с сохранения первого владельца мира; дальше каждое его новое сохранение уходит на сервер само (`F11` — загрузить вручную). |
| Старт миссии | Владелец мира начинает миссию — сервер переносит остальных на точку старта и подсказывает начать ту же миссию (тот же маркер). |
| Катсцены | Каждый смотрит свою. **Кто досмотрел раньше, у того мир замирает** (время остановлено, экран затемнён), пока не досмотрят все. Дальше все продолжают одновременно. Тех, кто ещё не начал миссию, ждут до 45 с; в подсказке сервер называет, кого ждут. Игрок, чья игра перестала отвечать (5 с), барьер не держит; переподключившийся посреди сцены снова ждётся. Смена владельца мира барьер не сбрасывает. |
| NPC миссии | Враги и спутники одной миссии **связываются между играми** по скрипту миссии, модели и месту. Копия у каждого — его собственный персонаж миссии со своим ИИ и анимациями, но здоровье, смерть и положение — как у владельца мира. Враг, убитый у владельца, умирает у всех, поэтому цели «убить всех» выполняются в каждой игре. Попадания любого игрока засчитываются у владельца. |
| Урон | Решает владелец мира: копии NPC у остальных стреляют «вхолостую», настоящий урон приходит от оригиналов. Без двойного урона. |
| Смерть в миссии | Погиб один — миссия перезапускается с чекпоинта у всех (если у кого-то идёт катсцена — после неё, даже если он за это время переподключился). |
| Разные миссии | Сервер сравнивает, кто какую миссию играет, предупреждает и не держит барьер ради чужой миссии. Цепочки миссий, свободное перемещение и неизвестные скрипты ложных предупреждений не дают. |
| Передача сохранений | Прерванная переподключением загрузка или скачка продолжается сама; сохранение, сделанное без связи, уходит на сервер при подключении. Загружать сохранение кампании может только владелец мира, скачанное с сервера обратно не отправляется. |

### `host` — гости в мире владельца

Миссии идут только у владельца мира. Остальные видят его мир, а во время его катсцен **смотрят их
через камеру владельца**: ракурс, движение камеры и положение персонажей совпадают, но лицевых
анимаций и озвучки нет. Мир вокруг сцены в это время передаётся с полной частотой, зрители
неуязвимы. После сцены тех, кто далеко, сервер переносит к владельцу.

### Во всех режимах

- Метку на карте видят все («Friend's waypoint»).
- Пассажиры: можно сесть в повозку другого игрока, править чужой повозкой или лошадью — третий
  игрок видит её по потоку того, кто правит, а не по эху владельца мира.
- Если владелец мира ушёл, пока вы сидите на его лошади или в его повозке, она остаётся у вас
  обычной лошадью/повозкой, а не исчезает.
- Пока кто-то в катсцене, остальные неуязвимы.

## Установка

**Каждому игроку:**

1. Установите [Script Hook RDR2](http://www.dev-c.com/rdr2/scripthookrdr2/) (`ScriptHookRDR2.dll`
   и `dinput8.dll` — в папку с `RDR2.exe`).
2. Скопируйте туда же `RDR2Coop.asi` и `RDR2Coop.ini`. Готовые файлы есть в GitHub Actions
   (**Actions → build → Artifacts**), либо [соберите сами](#сборка).
3. Укажите в `RDR2Coop.ini` адрес сервера, кампанию и имя.

**Сервер — один из двух вариантов:**

- **Отдельный сервер** (VPS, домашний ПК, любой Linux или Windows):
  ```
  rdr2coop-server --port 27960 --data ./rdr2coop-data --password секрет
  ```
  Параметры: `--mode shared|host`, `--max-players 8`, `--barrier-timeout 120`, `--no-barrier`,
  `--no-shared-fail`, `--memory` (ничего не хранить на диске). Данные лежат в
  `rdr2coop-data/<кампания>/`: `saves/`, `journal.log`, `players.ini`.
- **Сервер внутри игры у одного из игроков:** `host_server = 1` в его `RDR2Coop.ini`. Сервер
  работает в отдельном потоке, поэтому не замирает на загрузочных экранах. Данные лежат в
  `RDR2Coop-server\` рядом с модом. Остальные указывают его IP в `server =`.
  Нужен доступный UDP-порт 27960: проброс порта или виртуальная сеть (Radmin VPN, ZeroTier, Tailscale).

Протокол — **версия 6**: мод у всех игроков и сервер нужно обновлять вместе (при несовпадении
мод пишет «version mismatch»). Защита сервера: рукопожатие с cookie (поддельный адрес не создаёт
состояния и не получает в ответ больше, чем прислал), не больше 16 подключений с одного адреса,
10 неверных паролей в минуту с адреса, ограничения частоты и объёма сообщений для каждого игрока.
Отдельный сервер по Ctrl+C / SIGTERM сразу сообщает игрокам об остановке.

```ini
[network]
server = 203.0.113.5        ; или пусто + host_server = 1
port = 27960
campaign = blackwater
password = секрет
world_owner = 1             ; этот игрок хочет вести мир (обычно тот, чьё сохранение — сюжет кампании)
```

## Управление

| Клавиша | Действие |
|---|---|
| `F7` | Подключиться / отключиться |
| `F8` | Телепортироваться к владельцу мира (или к ближайшему игроку) |
| `F9` | Показать / скрыть строку состояния |
| `F10` | Скачать сохранение кампании с сервера |
| `F11` | Загрузить своё последнее сохранение на сервер |

В строке состояния видны: кампания, число игроков, владелец мира, пинг, трафик, ближайший игрок,
задержка сглаживания, число объектов, сколько мод тратит за кадр, а также состояние сюжета
(ожидание, катсцены, расхождение миссий, передача сохранения). После загрузки сохранения мод
переподключается сам. Журнал клиента — `RDR2Coop.log`.

## Порядок игры (shared)

1. Запускается сервер. Владелец мира подключается первым — его сохранение становится сохранением кампании.
2. Остальные подключаются, нажимают `F10` и загружают полученное сохранение (мод переподключится сам).
3. Владелец идёт к миссии и начинает её — остальные оказываются рядом и начинают ту же миссию.
4. Дальше сервер сам ждёт на катсценах, связывает NPC и перезапускает миссию при гибели.
5. Сохраняется владелец мира, его сохранение уходит на сервер. Если прохождения разошлись,
   всем достаточно снова нажать `F10`.

## Плавность и оптимизация

- Свой персонаж — 30 обновлений в секунду (5 — когда стоит), мир — 15.
- Надёжный канал с выборочным подтверждением и тайм-аутом повтора по измеренному RTT:
  потерянный пакет повторяется один, а не всё окно. Передача сохранения — 290–440 КБ/с
  (раньше 10–12 КБ/с), накладные расходы ≈ 1,1 байта в сети на байт данных.
- Сервер пересылает без выделения памяти на сообщение: на 8 игроков и 80 NPC −30% инструкций.
- Адаптивный буфер джиттера: задержка подстраивается под сеть, часы воспроизведения не прыгают.
- Движение между пакетами — по сплайну Эрмита с учётом скорости: в тесте с задержкой 60–140 мс,
  перемешиванием и 10% потерь ошибка траектории около 1 см.
- Персонажи идут с упреждением, походка плавно смешивается, мелкие отклонения мягко доводятся.
  Ошибка слежения: восьмёрка — 0,18 м в среднем (было 0,33), галоп 12 м/с — 0,34 м (было 1,59),
  остановка — точно на месте, без проскока. Провал связи на 300 мс — ошибка 1 см, без рывка.
- Приоритеты по расстоянию до ближайшего игрока, отправка только изменений, ключевой кадр раз
  в секунду, компактное кодирование (обновление идущего NPC — 14 байт): **80 NPC + игрок ≈ 5 КБ/с**.
- Гистерезис границы зоны, пул переиспользования объектов, предзагрузка моделей, LOD по
  процессору у зрителей, кэш запросов к игре за кадр.
- Вызовов игровых функций за кадр: у владельца мира в оживлённом городе 142 вместо 416, у гостя
  74–113 вместо 166; один проход по пулам сущностей на всех игроков сразу; дальние NPC
  перепроверяются раз в секунду.

## Известные ограничения

- **Мир просчитывает игра владельца** — без подключённого владельца мира не будет и мира. Сервер
  передаёт его следующему игроку сразу, но мир при этом начинается заново (его мир, его NPC).
- **Режим `host`:** катсцены у зрителей без лицевых анимаций и озвучки (движок не даёт
  воспроизвести чужую сцену). Для полноценных катсцен — `shared`.
- **Режим `shared`:**
  - каждый сам запускает миссию на том же маркере (мод переносит туда и подсказывает);
  - миссии с выбором могут разойтись, если игроки выберут по-разному;
  - провал миссии не из-за смерти синхронно не перезапускается;
  - сюжетные персонажи, которых у игрока нет, показываются копиями без собственного ИИ.
- **Поезда** не синхронизируются.
- **Анимации копий NPC** (в `host` и для несвязанных NPC) приблизительные.
- Деньги и предметы у каждого свои.

## Что проверить в игре первым делом

Строка состояния (HUD) рисуется функциями `UIDEBUG::_BG_*` — функции `HUD::` для текста в
современных версиях игры пустые. Если строки не видно, дело в них (`plugin/hud.h`).

Вызовы игровых функций сверены по сигнатурам с базой
[rdr3-nativedb](https://github.com/alloc8or/rdr3-nativedb-data), но их поведение в конкретной
версии игры может отличаться (`plugin/rdr2_game.cpp`):

- персонаж друга не виден → `spawn` (вариация одежды);
- персонажи дёргаются → `moveTo` / `standStill` / `nudge`; если «скользят», выключите `soft_correction`;
  если мерцают между шагом и бегом — граница походки в `moveBlend`;
- повозки и лодки ведут себя странно → `steerVehicle`;
- урон не проходит → `damageNpc`, `wasDamagedByLocalPlayer`;
- катсцена определяется как «идёт миссия и у игрока нет управления» (`readLocalPlayer`). Если
  барьер срабатывает не вовремя, запустите сервер с `--no-barrier`;
- NPC миссии не связываются → `listMissionEntities` / `GET_ENTITY_SCRIPT`, расстояние `kBindDistance`;
- сохранение не появляется в меню → проверьте файл `SRDR300xx` в папке профиля
  (`Документы\Rockstar Games\Red Dead Redemption 2\Profiles\…`) и перезапустите игру.

## Сборка

Нужны CMake ≥ 3.16 и компилятор C++17. SDK Script Hook **не нужен**: функции
`ScriptHookRDR2.dll` находятся при загрузке плагина (`plugin/scripthook.cpp`).

```bash
# Windows, Visual Studio 2019/2022 ("x64 Native Tools Command Prompt"):
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build          # → build/plugin/RDR2Coop.asi, build/rdr2coop-server.exe

# Linux: сервер и тесты
cmake -S . -B build && cmake --build build && ctest --test-dir build

# Linux → Windows (кросс-сборка, пакет g++-mingw-w64-x86-64):
cmake -S . -B build-win -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64-x86_64.cmake
cmake --build build-win
```

## Структура проекта

```
core/      переносимое ядро без зависимости от игры (тестируется на любой ОС)
  protocol        формат сообщений
  link            надёжный и быстрый каналы поверх UDP, рукопожатие, переподключение
  server          сервер: кампании, владелец мира, пересылка, копия мира, сюжет
  server_storage  сохранения (с историей), журнал, игроки — на диске или в памяти
  session         клиент: куклы игроков, зеркала, связка NPC миссий, приоритеты, урон
  story           клиентская часть сюжета: команды сервера, камера, метки, сохранения
  interp          адаптивный буфер джиттера + сплайн Эрмита
  game_api        интерфейс «что нужно от игры» (IGame)
plugin/    RDR2Coop.asi: IGame через natives, встроенный сервер, HUD, клавиши, сохранения
server/    rdr2coop-server
tests/     автотесты: сервер и клиенты в симулированной сети + симулированный мир
```
