# RDR2 Co-op — сюжет Red Dead Redemption 2 вдвоём

Мод для **одиночной (сюжетной) игры** RDR2 на ПК, который позволяет второму игроку
присоединиться к вашему миру: вместе ездить по карте, участвовать в перестрелках и проходить миссии.

> **Статус: экспериментальная версия 0.4.** Сетевое ядро и логика синхронизации покрыты
> автотестами, плагин собирается под Windows, но **в самой игре он ещё не обкатан** — у меня
> нет возможности запустить RDR2 в среде разработки. Первые запуски почти наверняка потребуют
> подстройки (см. [«Известные ограничения»](#известные-ограничения) и
> [«Что проверить в игре»](#что-проверить-в-игре-первым-делом)).

Мод работает только в сюжетном режиме и не имеет отношения к Red Dead Online
(Script Hook в Online не загружается).

## Как это устроено

RDR2 не рассчитана на двоих в сюжете, поэтому мод строит совместную игру поверх двух обычных
одиночных игр:

| | Хост | Гость |
|---|---|---|
| Чей сюжет | Его миссии, его мир, его сохранение | Заходит в мир хоста |
| Персонаж друга | «Кукла»: движение, оружие, стрельба, прицеливание, присед, падения, езда верхом и в транспорте | то же |
| Люди, животные, лошади | Настоящие, управляются игрой | «Зеркала» хоста; своё население отключено |
| Повозки, телеги, лодки | Настоящие | Зеркала, с пассажирами и возницами на своих местах |
| Урон | Решает хост | Попадания гостя пересылаются хосту и наносятся настоящим NPC |
| Время суток и погода | Источник | Подстраиваются под хоста |
| Одежда | NPC и персонажи выглядят так же, как у владельца | то же |

- Каждый игрок управляет своим персонажем локально, без задержки ввода.
- Враги хоста видят гостя и стреляют по нему, урон приходит гостю по сети.
  NPC целятся в того, в кого целятся у хоста.
- **Управление передаётся.** Если гость сядет на козлы повозки хоста или на его лошадь,
  у хоста настоящая повозка или лошадь едет по командам гостя. Так работают миссии,
  где нужно править повозкой.
- **Миссии и катсцены.** Когда хост начинает миссию далеко от гостя, гость переносится к нему.
  Пока хост смотрит сюжетную сцену, гость неуязвим, а после сцены снова оказывается рядом
  (`auto_regroup`, `regroup_distance`).
- Связь — UDP: напрямую по IP либо через маленький relay-сервер (без проброса портов).
  При обрыве и после загрузки сохранения мод сам переподключается.

### Плавность

- Свой персонаж отправляется 30 раз в секунду, мир — 15 раз в секунду.
- Движение воспроизводится с небольшой задержкой через **адаптивный буфер джиттера**.
  Задержка подстраивается под реальную сеть: на хорошем соединении ~50 мс, на плохом больше,
  но без рывков. Часы воспроизведения не прыгают: при сбоях сети они чуть ускоряются
  или замедляются.
- Между пакетами положение строится по **сплайну Эрмита** с учётом скорости, поэтому повороты
  идут дугой, а не ломаной. В тесте с задержкой 60–140 мс, перемешиванием пакетов и 10% потерь
  ошибка траектории — около 1 см.
- Поворот на месте идёт плавно, вслед за потоком, а не рывками по 25°. Транспорт
  поворачивает с учётом времени кадра, одинаково при 30 и 144 FPS.
- Персонажи идут к точке с упреждением и с подходящей скоростью (шаг, бег и галоп плавно
  смешиваются). Мелкие отклонения мягко доводятся («мягкая коррекция»), телепорт — только
  при большом расхождении.
- Время измеряется точным таймером (`QueryPerformanceCounter`), а не `GetTickCount`
  с шагом 16 мс.

### Оптимизация

- **Приоритеты по расстоянию:** ближние объекты (до 30 м) обновляются 15 раз в секунду,
  средние — 7, дальние — 4. Объекты в бою и едущий транспорт — чаще.
- **Отправляются только изменения:** у стоящего NPC — один ключевой кадр в секунду.
  Изменение повторяется ещё ~200 мс на случай потери пакета.
- **Компактное кодирование:** позиция — 6 байт (шаг 2 см от опорной точки), направление — 2,
  скорость — 3. Обновление идущего NPC занимает 14 байт вместо 30.
- Стоящий игрок отправляет состояние 5 раз в секунду вместо 30. Начало движения или выстрел
  уходят сразу.
- Итог в тесте: **80 NPC + игрок ≈ 5 КБ/с** (в версии 0.1 только NPC заняли бы ~24 КБ/с).
- **Гистерезис зоны:** объект входит в зону на `radius`, а выходит на `radius + 20 м`, поэтому
  у границы ничего не мерцает и не пересоздаётся.
- **Пул объектов:** ушедшие из зоны зеркала не удаляются, а прячутся на 10 секунд. Следующий
  объект той же модели появляется мгновенно, без создания и загрузки модели.
- **Упреждающая загрузка моделей** для объектов, ждущих своей очереди появления.
- **LOD по процессору у гостя:** ближние зеркала обновляются каждый кадр, средние — через кадр,
  дальние — раз в 4 кадра (транспорт — не реже раза в 2 кадра). Движение считается по времени,
  поэтому от этого не замедляется. В тесте дальнее зеркало стоит в 4 раза меньше обращений к игре.
- **Кэш запросов к игре за кадр:** позиция, здоровье и существование объекта запрашиваются
  у игры один раз за кадр. Неизменные признаки (игрок ли это, упряжная ли лошадь, поезд ли)
  запоминаются на несколько секунд.
- В строке состояния видно, сколько мод тратит: миллисекунды и число вызовов игровых функций
  за кадр.
- Игра опрашивается полностью только для объектов, у которых подошла очередь обновления.
- У гостя посторонние NPC и транспорт **удаляются**, а не прячутся, чтобы не тратить время
  на их ИИ и физику. Только сюжетные объекты скрываются, чтобы не ломать скрипты.
- Задачи ИИ не перевыдаются каждый кадр, а только при заметном изменении (~4–5 раз в секунду).
  Буферы переиспользуются, в игровом цикле нет лишних выделений памяти.

## Установка (оба игрока)

1. Установите [Script Hook RDR2](http://www.dev-c.com/rdr2/scripthookrdr2/) (Alexander Blade):
   `ScriptHookRDR2.dll` и `dinput8.dll` — в папку с `RDR2.exe`.
2. Скопируйте туда же `RDR2Coop.asi` и `RDR2Coop.ini`.
   Готовые файлы собираются в GitHub Actions (вкладка **Actions → build → Artifacts**),
   либо соберите сами — см. [«Сборка»](#сборка).
3. Настройте `RDR2Coop.ini` (ниже) и запустите сюжетную игру.

## Настройка соединения

Один игрок — `role = host`, второй — `role = guest`. Версии мода должны совпадать.

**Вариант А: напрямую.** У хоста должен быть доступен UDP-порт `27960`: проброс порта на роутере
или виртуальная локальная сеть (Radmin VPN, ZeroTier, Tailscale, Hamachi).

```ini
; хост                         ; гость
[network]                      [network]
role = host                    role = guest
connection = direct            connection = direct
port = 27960                   address = IP_ХОСТА
                               port = 27960
```

**Вариант Б: через relay** — если порты открыть нельзя. Запустите `rdr2coop-relay` на любой
машине с белым IP (подойдёт самый дешёвый VPS; есть сборки под Linux и Windows):

```
./rdr2coop-relay 27960
```

Оба игрока указывают адрес relay и одинаковое имя комнаты:

```ini
[network]
role = host            ; у второго игрока — guest
connection = relay
address = АДРЕС_RELAY
port = 27960
room = наша-тайная-комната
```

Relay только пересылает пакеты между двумя участниками комнаты и не хранит состояние игры.

## Управление

| Клавиша | Действие |
|---|---|
| `F7` | Подключиться / отключиться |
| `F8` | Телепортироваться к другу |
| `F9` | Показать / скрыть строку состояния |
| `F10` | Гость: скопировать сохранение хоста (режим `shared`) |

В строке состояния видны пинг, трафик в обе стороны, расстояние до друга, текущая задержка
сглаживания и число синхронизированных объектов.

В `RDR2Coop.ini` настраиваются клавиши, имя, модель персонажа (`avatar`), радиус синхронизации
(`radius`), лимиты (`max_peds`, `max_vehicles`), синхронизация времени и погоды, мягкая коррекция
и дружественный огонь. Журнал пишется в `RDR2Coop.log`.

## Сюжет вдвоём

Есть два режима (`[story] mode` в `RDR2Coop.ini`, у обоих одинаковый).

### `shared` — общий сюжет (по умолчанию). Катсцены смотрят оба

Оба играют **одно и то же сохранение**, поэтому каждая миссия идёт в обеих играх, и каждый видит
настоящие катсцены — с анимацией, озвучкой и субтитрами. Мод держит два прохождения в такт.

| Что | Как работает |
|---|---|
| Одинаковое сохранение | Гость нажимает **`F10`** — последнее сохранение хоста копируется по сети в свободный слот гостя (`SRDR30000`…`SRDR30014`, свои сохранения не перезаписываются, целостность проверяется по CRC-32). Затем гость загружает его: пауза → Сюжет → Загрузить игру. |
| Старт миссии | Хост начинает миссию — гость переносится на точку старта и видит подсказку начать ту же миссию (тот же маркер на карте). |
| Катсцены | Каждый смотрит свою. **Кто досмотрел первым, у того мир замирает** (время остановлено, экран затемнён), пока не досмотрит второй. Потом оба продолжают одновременно. Если друг ещё не начал миссию, ожидание длится до 45 с. |
| NPC миссии | Враги и спутники одной миссии **связываются между играми** по скрипту миссии, модели и месту. Связанный NPC у гостя — это его собственный персонаж миссии со своим ИИ и анимациями, но здоровье, смерть и положение берутся у хоста. Враг, убитый у хоста, умирает и у гостя, поэтому цели «убить всех» выполняются в обеих играх. Выстрелы гостя по своему двойнику засчитываются у хоста. |
| Урон | Решает хост: связанные NPC у гостя стреляют «вхолостую», настоящий урон гостю приходит от их оригиналов у хоста. Без двойного урона. |
| Смерть в миссии | Погиб один — миссия перезапускается с чекпоинта у обоих (`shared_fail`). Если у второго в этот момент катсцена, перезапуск наступит после неё. |
| Разные миссии | Мод сравнивает, какую миссию играет каждый, и предупреждает, если они разные (например, разные сохранения). Ждать чужие катсцены в этом случае не будет. |

### `host` — гость в мире хоста

Миссии идут только у хоста, гость видит его мир. Во время катсцен хоста **гость смотрит их через
камеру хоста** (`spectate`): ракурс, движение камеры и положение персонажей совпадают, но анимаций
лиц и жестов, а также озвучки у гостя нет. Мир вокруг сцены в это время передаётся с полной
частотой, гость неуязвим. После сцены, если гость далеко, он переносится к хосту.

### В обоих режимах

- Метка пути, поставленная на карте, видна другу как «Friend's waypoint».
- Когда хост начинает миссию далеко, гость переносится к нему.

### Порядок игры (shared)

1. Хост сохраняется. Оба подключаются (`F7`), гость нажимает `F10` и загружает полученное сохранение.
2. Оба подключаются снова (после загрузки сохранения мод переподключается сам).
3. Хост идёт к миссии и начинает её — гость оказывается рядом и начинает ту же миссию.
4. Дальше мод сам ждёт, связывает NPC и перезапускает миссию при гибели.
5. Сохраняться лучше обоим в одной точке (например, после миссии), чтобы прохождения не разошлись.

## Известные ограничения

- **Только два игрока.**
- **Режим `host`:** катсцены у гостя без анимаций актёров и озвучки (движок не даёт
  воспроизвести чужую сцену). Для полноценных катсцен используйте `shared`.
- **Режим `shared`:**
  - миссию гостю нужно запустить самому, на том же маркере (мод переносит туда и подсказывает);
  - миссии с выбором (диалог, развилка) могут разойтись, если игроки выберут по-разному;
  - провал миссии не из-за смерти (например, упустили цель) синхронно не перезапускается;
  - сюжетные персонажи, которых у гостя нет (или которые далеко ушли), показываются копиями
    без собственного ИИ.
- **Поезда** не синхронизируются.
- **Анимации копий NPC** (в `host` и для несвязанных NPC) приблизительные: ходьба, бег,
  стрельба, прицеливание, падения, езда. Без укрытий и рукопашной.
- Прогресс, деньги и предметы не синхронизируются: в `shared` каждый копит своё, в `host`
  сохраняется только сюжет хоста.

## Что проверить в игре первым делом

Вызовы игровых функций (natives) сверены по сигнатурам с базой
[rdr3-nativedb](https://github.com/alloc8or/rdr3-nativedb-data), но их поведение в конкретной
версии игры может отличаться. Если что-то работает не так, смотреть сюда (`plugin/rdr2_game.cpp`):

- кукла друга не видна → `spawnPed` (вариация одежды `SET_RANDOM_OUTFIT_VARIATION`);
- кукла дёргается или не идёт → `moveTo` / `standStill` / `nudge`, пороги в `CoopSession::movePed`;
  если персонажи «скользят», выключите `soft_correction`;
- повозки/лодки ведут себя странно → `steerVehicle` (управление через скорость);
- урон не проходит → `damageNpc`, `wasDamagedByLocalPlayer`;
- у гостя остаются свои прохожие → `suppressAmbientPopulation`, `removeForeign`;
- нет текста на экране → `drawText` в `plugin/main.cpp`;
- катсцена определяется как «идёт миссия и у игрока нет управления» (`readLocalPlayer`);
  если барьер срабатывает не вовремя — начать отсюда;
- NPC миссии не связываются → `listMissionEntities` / `GET_ENTITY_SCRIPT`, расстояние
  `kBindDistance` в `core/session.cpp`;
- сохранение не появляется в меню → проверьте файл `SRDR300xx` в папке профиля
  (`Документы\Rockstar Games\Red Dead Redemption 2\Profiles\…`), перезапустите игру.

## Сборка

Нужны CMake ≥ 3.16 и компилятор C++17. SDK Script Hook **не требуется** — библиотека импорта
генерируется из `plugin/ScriptHookRDR2.def`.

```bash
# Windows, Visual Studio 2019/2022 ("x64 Native Tools Command Prompt"):
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build          # → build/plugin/RDR2Coop.asi, build/rdr2coop-relay.exe

# Linux: тесты и relay
cmake -S . -B build && cmake --build build && ctest --test-dir build

# Linux → Windows (кросс-сборка, пакет g++-mingw-w64-x86-64):
cmake -S . -B build-win -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64-x86_64.cmake
cmake --build build-win      # → build-win/plugin/RDR2Coop.asi
```

## Структура проекта

```
core/      переносимое ядро без зависимости от игры (тестируется на любой ОС)
  protocol   формат сообщений
  link       соединение двух игроков: рукопожатие, надёжный канал, переподключение, relay
  relay      логика relay-сервера
  interp     адаптивный буфер джиттера + сплайн Эрмита
  session    логика кооператива: куклы, зеркала, связка NPC миссий, приоритеты, урон
  story      сюжет: старт миссий, барьер катсцен, общий провал, камера хоста, метки, сохранения
  game_api   интерфейс «что нужно от игры» (IGame)
plugin/    RDR2Coop.asi: реализация IGame через natives, HUD, горячие клавиши, сохранения
server/    rdr2coop-relay
tests/     автотесты: симулированный мир с движением + сеть с задержкой, джиттером и потерями;
           проверяют плавность, точность слежения и расход трафика
```

## Планы

Поезда, одежда NPC, катсцены для гостя (режим зрителя), укрытия и рукопашная,
более двух игроков.
